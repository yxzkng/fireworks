# 동시 접속 대응 계획

**결론: 해결 가능합니다.** 다만 현재 구조는 **약 100명에서 무너집니다.**
원인은 트래픽 양이 아니라 설계 결함 하나이고, 고치면 무료 티어로도 3,000명을 감당합니다.

---

## 지금 무슨 일이 일어나는가

가장 큰 문제는 **제보 1건이 올라올 때마다 접속자 전원이 300행을 다시 읽는** 구조입니다.

```
web/public/index.html:700
  .on('postgres_changes', {...}, loadReports)   ← 이벤트마다 loadReports() 통째 재실행

web/public/index.html:450
  .select('*')...limit(300)                     ← 매번 300행 전체 조회
```

접속자 N명, 분당 제보 M건이면 **N × M × 300행**. 곱셈으로 늘어납니다.

| 접속자 | 분당 재조회 | Supabase egress (12시간) | 한도 5GB |
|---:|---:|---:|:--|
| 100 | 200회 | **17 GB** | ❌ 초과 |
| 500 | 5,000회 | **432 GB** | ❌ |
| 1,000 | 20,000회 | **1,728 GB** | ❌ |

정작 필요한 건 **새로 올라온 1행**인데 300행을 받습니다.

### 그 외 확인된 한도

조사한 실제 수치입니다.

| 항목 | 무료 한도 | 현재 구조에서 |
|---|---|---|
| Supabase 실시간 **동시 연결** | **200** | 201명째부터 구독 실패 |
| Supabase 실시간 메시지 | 200만/월 | 200명이면 하루에 월분 소진 |
| Supabase egress | 5GB/월 | 100명에서 초과 |
| Supabase Storage | 1GB | 사진 약 3,300장에서 참 |
| Vercel 대역폭 | 100GB/월 | 3,000명까지는 여유 |

**동시 연결 200**이 가장 먼저, 가장 단단하게 막힙니다. 이건 늘릴 수 없는 값입니다.

### 사진은 별도 병목

현재 1600px(약 300KB) 원본을 카드 목록 썸네일에 그대로 씁니다.
목록에 장소별 3장씩 최대 57장이 노출되므로:

- 접속 500명 × 57장 = **8.6GB** → 한도 초과
- 접속 1,000명 = **17GB**

## 고칠 것 (효과 순)

### 1. 재조회 폐지 — ✅ 적용 완료 (2026-09-01)

실시간 이벤트에는 **새 행이 이미 담겨 옵니다**. 그걸 쓰지 않고 전체를 다시 읽는 게 문제입니다.

- `loadReports` 재호출 대신 `payload.new`를 로컬 배열에 병합
- INSERT면 추가, UPDATE면 교체, `hidden`이면 제거
- 전체 조회는 **최초 1회만**

**적용 결과**: egress가 제보 수와 무관해져, 예상(300배)보다 큰 개선이 나왔습니다.

| 접속자 | 개선 전 | 개선 후 |
|---:|---:|---:|
| 100 | 17.3GB | 0.012GB |
| 1,000 | 1,728GB | 0.12GB |
| 3,000 | 15,552GB | 0.36GB |

이제 egress는 "접속자 수 × 최초 1회"뿐입니다. 제보가 아무리 올라와도 늘지 않습니다.

함께 고친 것 — `schema.sql`의 읽기 정책을 `hidden = false` → `true`로 바꿨습니다.
Realtime은 RLS가 SELECT를 막는 행의 이벤트를 조용히 버리기 때문에, 그대로 두면
"신고 3건으로 숨겨짐" UPDATE가 구독자에게 전달되지 않아 다른 사람 화면에는
그 제보가 계속 남습니다. 걸러내기는 클라이언트가 합니다.

### 2. 실시간 구독 → 증분 폴링 — ✅ 적용 완료 (2026-09-01)

동시 연결 200은 우회가 불가능하니, 축제 당일에는 구독을 쓰지 않는 편이 안전합니다.

- 30초마다 `created_at > 마지막본시각` 인 행만 조회 (보통 0~2행)
- 연결을 붙들지 않으므로 **접속자 수 제한이 사라짐**
- 30초 지연은 이 서비스에 충분 (혼잡도 원본이 5분 주기)

**적용 결과**: 실시간 구독을 쓰지 않으므로 **동시 연결 200 한도가 사라졌습니다.**
접속자 수 상한이 없어지고 egress만 남습니다.

| 접속자 | egress (12시간) | 한도 5GB |
|---:|---:|:--|
| 1,000 | 1.50GB | ✅ |
| 3,000 | 4.51GB | ✅ |
| 5,000 | 7.51GB | ⚠️ |

`index.html`의 `SYNC_MODE`를 `'realtime'`으로 바꾸면 구독 방식으로 되돌아갑니다
(양쪽 다 테스트 완료). 접속이 적을 때는 구독이 더 빠릅니다.

**함께 조정한 것 — sweep 주기**: 폴링만으로는 "신고로 숨겨진 제보"를 감지할 수 없습니다.
`created_at`이 바뀌지 않아 증분 조회에 걸리지 않기 때문입니다. 그래서 주기적으로
화면의 제보가 숨겨졌는지 id로 확인하는데(`sweepHidden`), 처음 잡은 2.5분 주기로는
**이 조회가 전체 egress의 73%**를 차지했습니다. 10분 주기로 늘리고 검사 대상도
화면에 실제 보이는 80건으로 줄여 4.73GB → 1.50GB가 됐습니다.
신고된 제보가 최대 10분 늦게 사라지지만, 급한 일이 아닙니다.

### 3. 썸네일 분리 — ✅ 적용 완료 (2026-09-01)

업로드 시 **240px 썸네일을 함께 만들어** 나란히 저장합니다.
목록과 상세 타임라인은 썸네일만 쓰고, 원본은 **확대해서 볼 때만** 불러옵니다.

**실측값** (4032×3024, 1.2MB 사진 기준):

| | 크기 |
|---|---:|
| 원본 (1280px, q0.82) | 204KB |
| 썸네일 (240px, q0.72) | **12KB** |

**17배 차이**입니다.

| 접속자 | 개선 전 | 개선 후 |
|---:|---:|---:|
| 500 | 6.0GB | 0.37GB |
| 1,000 | 11.9GB | 0.73GB |
| 3,000 | 35.7GB | 2.20GB |

원본도 1600px → 1280px로 낮춰(300KB → 204KB) 저장 가능 건수가
약 3,300건 → **4,500건**으로 늘었습니다.

캐시 헤더도 1시간 → 1년으로 바꿨습니다. 사진은 한 번 올라가면 바뀌지 않으므로
재방문자와 같은 사진을 여러 번 보는 경우 전송이 아예 일어나지 않습니다.

### 4. 혼잡도 응답 경량화 + 폴링 주기 조정

- 목록에 필요한 건 현재 혼잡도뿐인데 **12시간 예측까지 매번** 내려보냅니다 (25KB)
  → 목록용 요약(3KB)과 상세용을 분리
- 폴링 60초 → **5분** (서버가 5분마다 수집하는데 1분마다 물어볼 이유가 없음)
- `Cache-Control: s-maxage=60`은 이미 있으나, CDN이 실제로 태우는지 확인 필요
  → 함수 실행이 접속자 수와 무관하게 720회/일로 고정되는지 검증

> 3,000명 기준 54GB → 6.5GB

### 5. 방어 장치

- **제보 속도 제한**: 같은 브라우저에서 30초 내 재제보 차단 (스팸·오작동 방지)
- **사진 용량 상한**: 서버에서 거부할 최대 크기 지정
- **읽기 전용 대비**: 저장소가 한도를 넘겨도 혼잡도·지도·카드는 계속 보이게
  (이미 그렇게 되어 있으나, 제보 실패 시 안내 문구를 명확히)

## 무료 티어로 안 되는 경우

수만 명 규모를 예상한다면 돈으로 해결하는 게 확실합니다.

- **Supabase Pro $25/월** — egress 250GB, 동시연결 500. 축제 한 달만 쓰고 내려도 됩니다.
- **Vercel Pro $20/월** — 대역폭 1TB. 더 중요한 건 **Hobby는 상업적 이용 금지**라
  공개 서비스는 약관상 회색지대라는 점입니다.

두 개 합쳐 **$45으로 한 달**이면 수만 명도 감당합니다.

### 유료도 쓰지 않겠다면

- 사진 업로드를 끄고 **혼잡도 + 텍스트 제보만** 운영 (대역폭의 대부분이 사진)
- 제보를 **읽기 전용**으로 두고 공공데이터만 노출 (이러면 사실상 무한 확장)

## 반드시 알아둘 위험

1. **무료 티어는 초과 시 차단이지 과금이 아닙니다.** 축제 당일 트래픽이 몰리면
   서비스가 멈춥니다. 예측이 어렵다면 유료 전환이 보험입니다.
2. **Supabase 무료 프로젝트는 1주 미사용 시 자동 일시정지**됩니다.
   9/5 전에 반드시 한 번 열어 깨워두세요.
3. **Vercel Hobby는 상업적 이용 금지**입니다. 무료·비영리 공개 서비스라도
   규모가 커지면 문제 소지가 있습니다.
